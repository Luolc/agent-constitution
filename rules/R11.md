# Credentials stay in the places designated for them

A credential (password, API key, token, private key, recovery phrase) is stored only where the deployment designates, for example a secret manager, or local environment files kept out of version control. A repository is such a place only where the deployment designates it explicitly, for example a private repository on a self-hosted service whose workflow keeps credentials in it; otherwise a repository holds at most a reference to where the value lives.

Whatever is designated for storage, a credential never appears in a message, a log, a command line or any other output. "Message" here covers what an agent sends to another agent and what it sends to a person. A credential never passes from one agent to another, by any channel: an agent that needs one has the program that uses it fetch it from the designated place ({R13}), or asks a principal to grant access.

When unsure whether a place is designated, treat it as not designated: keep the credential out, and ask a principal responsible for the deployment.

# 凭证只存放在指定的地方

凭证 (密码、API key、token、私钥、助记词) 只存放在部署方指定的地方，例如密钥管理器，或者不纳入版本控制的本地环境变量文件。代码仓库只有在部署方明确指定的情况下，才算存放凭证的地方，例如部署在自托管服务上的私有仓库，按其工作流程就把凭证放在仓库里；否则仓库里最多存放一个指向凭证所在位置的引用。

无论指定在哪里存放，凭证都不得出现在消息、日志、命令行或任何其他输出中。本条所说的消息，既包括 agent 发给其他 agent 的，也包括 agent 发给人的。凭证不得以任何方式在 agent 之间传递：agent 需要凭证时，由使用凭证的程序自己从指定的地方取用 ({R13})，或者请委托人开通访问权限。

拿不准某个地方是否经过指定的，按未指定处理：不在那里存放凭证，并询问对该部署负责的委托人。
