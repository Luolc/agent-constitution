# 静态网站

构建出的宪法也发布成静态网页，英文在 `site/index.html`，中文在 `site/zh/index.html`，各自的 agent 版在下面的 `agent/` 里 (`site/agent/index.html`、`site/zh/agent/index.html`)，完整版在 `editions/<edition>/` 下还有一份 (`site/editions/2026-10/index.html`、`site/zh/editions/2026-10/index.html`)；本设计也发布在 `design/` 下 (`site/design/index.html`、`site/zh/design/index.html`)，规定发布在 `rules/` 下 (`site/rules/index.html`、`site/zh/rules/index.html`)。页面由 Hugo 用 `hugo-0.167.0 -s web` 构建，前提是 `uv run site-rules` 已经写出规定的数据 (见下文「规定」)。CI 在每个 pull request 和每次推送上运行四步：`uv run site-rules`、`uv run count-tokens` (统计 token，见下文)、`hugo-0.167.0 --source web --cleanDestinationDir --panicOnWarning`，以及链接检查 `uv run check-site-anchors site`，然后截图 (见下文「截图」)。工作流 `.github/workflows/pages.yml` 把网站发布到 GitHub Pages 上的 `https://agent-constitution.luolc.com/`，并把这个地址作为 `--baseURL` 传给 Hugo。

- 发布：每次推送到 `main`，以及手动运行时，job `build` 统计 token (见下文)，像 CI 一样构建并检查网站，然后上传；job `deploy` 发布网站，但只在仓库是公开的、并且仓库变量 `PAGES_DEPLOY` 为 `true` 时才运行，否则跳过。网站上线算一次发布 (第 32 号规定，`release-must-ask`)：设置这个变量，就是人同意发布此后每一次推送到 `main` 的内容；删除它，就停止发布。自定义域名在仓库的 Pages 设置里配置，来源选「GitHub Actions」；由工作流发布时会忽略 `CNAME` 文件，所以仓库里没有这个文件。在发布的构建里，页面之间的链接保持相对路径 (`relativeURLs`)；canonical 链接、各语言的 alternate 链接和 `og:url` 是绝对地址，用的是这个域名。`web/hugo.toml` 里的 `baseURL` 保持为 `/`：如果是绝对地址，主题会给样式表链接加上 `integrity` 和 `crossorigin`，以文件方式打开的页面就会丢掉样式。
- 输入：版目录 `generated/` 下生成的 `constitution.<lang>.md` ([宪法](constitution.md))，而不是源文件：引用、编号和锚点只由 `statute constitution build` 渲染一次。`web/hugo.toml` 把它们和版目录的 `index.toml` 从 `constitution/` 挂载为 asset，partial `web/layouts/_partials/constitution/source.html` 按名字找到每个文件，除非恰好有一个文件匹配，否则构建失败；Python 不生成任何页面，只生成规定各页的数据 (见下文「规定」)。content adapter `web/content/_content.gotmpl` 把每个文件做成对应语言的首页：去掉完整版的文件头那一行 (agent 版没有这一行)，标题成为页面的标题，每个标题里的锚点 (`## <a id="general-provisions"></a>Article I. ...`) 成为该标题的 id，这样目录就能链接到它，页面还以 params 的形式拿到长度 (见下文)。完整版开头不是文件头那一行、一个空行和 `# ` 标题，或者 agent 版开头不是 `# ` 标题的，构建失败。布局 (`web/layouts/_partials/constitution/full.html`) 放置标题、标题下的列表，以及 `<div class="constitution">` 里的正文，样式表以这个元素为根。标题 (`web/layouts/_partials/constitution/title.html`) 没有主题加的 `#` 链接，名称和括号部分各自保持在一行内，所以窄屏上只会在括号前换行；它的字号选得让它在 1400 像素宽的桌面窗口里能排在一行。`index.toml` 中的修订号后面，在 `status` 为 `draft` 时跟着 `(draft)` (`(草案)`)。这些字样的中英文写在 `web/i18n/` 里。标题下面是一个不带项目符号的列表：修订号和长度 (见下文)，各自在标题下居中；正文里有星号时，还有星号说明，从栏的左边缘开始，比上面两行更小、更淡：先是星号，然后说明标了星号的部分是写给人看的背景 (宪法从哪里来、怎样组织、怎样修改)，以及带链接的 agent 版不收录这些部分。星号用强调色，小号加粗，不用上标，也不撑开行距；它往下移，直到中线略高于项编号括号的中线，顶部明显低于编号的顶部。星号说明和目录里的星号显示方式相同。
- agent 版：每份生成的 `constitution.<lang>.agent.md` 成为对应语言首页下的 `agent/` 页面，由同一个 content adapter 生成 (布局 `web/layouts/page.html`)，但正文保持原样：没有锚点，没有链接，只写给人类读者的条文只保留编号和一句指向完整版的说明。它的标题带 `{anchor=false}`，所以主题不给它们加 `#` 链接。标题下是一个与首页类似的列表，两行都居中：修订号，以及一个回到完整版的链接。侧边栏、语言切换 (切到另一种语言的 agent 版)、配色切换和目录都与首页相同，目录链接到 Hugo 给标题生成的 ID。
- 这一版的页面：完整版同时也是对应语言的 `editions/<edition>/` 页面。以后有新版占了首页，这个地址仍然是这一版；从网站外面链接某一版，就链到这里。content adapter 用首页的正文、标题和 params 生成它，它的布局 `web/layouts/editions/page.html` 像首页的布局一样排这些内容，两者都通过 `web/layouts/_partials/constitution/full.html`。它在侧边栏里没有条目，`bookHidden` 把它从主题自己的列表里隐去，`editions/` 这个 section 没有自己的页面 (`build` 的 `render` 和 `list` 都是 `never`)。由于首页的正文与它相同，这一版的页面带 `<meta name="robots" content="noindex">` (`web/layouts/_partials/docs/inject/head.html`)，搜索引擎只在首页收录一次这份正文。条款下那一行规定的链接从网站根目录写起 (`relLangURL`)，`relativeURLs` 再把它们改成相对于各页面的路径，所以从两个页面都能链到规定的页面。
- 设计：`docs/design/` 里的文件成为各语言 `design/` 下的页面，原地读取：`web/hugo.toml` 把 `docs/design/*.md` 和 `docs/design/zh/*.md` 挂载为 asset，由 content adapter `web/content/design/_content.gotmpl` 生成页面，不另存副本。`README.md` 就是 `design/` 这个页面本身，其他文件各是 `design/<name>/`，顺序按 README 的目录列表，侧边栏里的页面名取自列表里的链接文字；列表与目录里的文件对不上时构建失败。每个文件的 `# ` 标题成为页面的标题。英文页面读 `docs/design/`，中文页面读 `docs/design/zh/` 里的译文：去掉第一行，即英文文件的 SHA-256 (设计译文检查，见[检查程序](checkers.md#checkers))，每个标题的锚点 `## <a id="checks"></a>检查` 成为该标题的 id，与英文标题的相同。某个文件还没有译文时，它的中文页面显示英文原文，上面有一行说明还没有译文 (`本页还没有中文译文，下面是英文原文。`)；缺译文从不让构建失败，中文侧边栏的页面名取自中文 README，没有中文 README 时取自英文的。布局 (`web/layouts/design/all.html`) 把标题和正文放在 `<div class="design">` 里，字体、字号、栏宽和配色都与宪法相同，但排成普通文档：标题靠左，用主题的项目符号、表格和代码块。目录列出二级标题，与宪法页面相同；设计里目前没有更深的标题。
- 设计里的链接：链接是按 GitHub 上看到的文件写的，网站由链接渲染钩子 (`web/layouts/_markup/render-link.html`) 改写，源文件保持原样。相对链接按页面所读文件的目录解析，即 `docs/design/` 或 `docs/design/zh/`，所以译文里指向另一份设计文件的链接照英文写 (`rules.md#rules`)，指出 `docs/design/` 的链接多加一层 `../`。指向设计文件 (两个目录都算) 的链接，改指它在当前页面语言下的页面；指向生成的宪法 `constitution/<edition>/generated/constitution.<lang>.md` 的，改指该语言的首页；指向仓里其他文件的，改指 GitHub 上的文件 (`params.SourceRepo` 加 `/blob/main/`)。片段保留。指向一份没有页面的设计文件，或者指出仓库之外的链接，构建失败；指向不存在的文件的链接，交给设计译文检查。宪法页面上的链接，以及各处的绝对链接和单独的片段，保持原样。
- 规定：`uv run site-rules` (`tools/site`) 通过 `statute export` ([statute 命令](statute-command.md#export)) 读宪法和 `rules/*.toml`，statute 由它在本检出里用 `cargo run` 运行；它写出 `web/data/rules.json` (不提交)，由 Hugo 读取；没有这个文件时构建失败，所以 CI 和 `pages.yml` 在 Hugo 之前运行它。文件里对 `index.toml` 的每种语言，按 parent 树的顺序列出规定树的每个节点，同一节点的子节点按 ID 排序，每个节点带上它的编号：`R` 加 ID (`R12`)，由 `site_rules.py` 里的 `rule_label` 生成，编号只在这一处生成，模板只读节点的 `label`。每给一个 `--source <name>:<quadrant>:<dir>`，它还通过同一个导出读一个别的规定源的 `<dir>/rules/*.toml`，其中的 `R12` 指本仓的第 12 条规定，与 `requires` 的写法相同 ([规定源](rule-sources.md))。这些节点排在本仓的节点后面，按象限的顺序 (全局公开、全局私有、本仓公开、本仓私有) 一个规定源接一个规定源排列，编号是 `<name>:<id>` (`team:7`)；节点在字段或引用 (`{@rule:R12}`、`{@rule:team:7}`) 里提到别的规定源的节点时，链接到那个节点的页面。每个节点都记下它的规定源和规定源的象限；规定源不止一个时，节点的分组以它的规定源开头。每给一个 `--enabled <statute.lock>`，每条规定都标明这些 lock 文件里有没有它。私有层的审阅站两个参数都用；公开站点都不用，所以页面上不显示象限，也不显示启用与否。文件还对每个条款列出在 `authority` 里写了它的规定，对每个下面还有条款的条或款列出写了它或它下面某个条款的规定，每条规定只出现一次，按规定源和 ID 排序。`authority` 同时写了一个条款和它上面的条款 (项和它所在的款或条，款和它所在的条) 时，只算下面那个更具体的：规定只列在它写的最具体的那些条款下面，详情页也只列这些；`statute validate rules` 会对这样的一对条款给出警告 ([检查器](checkers.md#checkers)，第 5 项检查)。已被取代或已废止的规定有自己的页面，也在列表里，但不列在条款下面。content adapter `web/content/rules/_content.gotmpl` 生成列表 `rules/`，并给每个节点生成一页 `rules/<id>/`，别的规定源的节点是 `rules/<name>-<id>/`：用 ID 而不用 `slug`，因为 ID 永远不变。列表 (`web/layouts/rules/section.html`) 是一张带表头的表，一条规定占一行，按树的顺序：依次是编号、标题 (由样式表截到一行)、标题下面的要求 (statement) 和它的标记，整行链接到它的详情页；标记是它的状态、规定源的默认值是否启用它 (开启或关闭，按 `statute export` 算出的结果) 和它的 `uses`，各是一个图标或圆点，各占一个位置 ([前端](frontend.md#components))；给了 `--enabled` 时接着标明是否启用，规定源不止一个时再标出它所在规定源的象限，每项都是一个小标签。挂在另一条规定下的规定，标题前有一个箭头。one-of 在表里画成一个框 ([规定不挂在规定下面](rule-config.md#no-rule-under-a-rule))，框线上写着「择一」：先是它自己的一行，再往下每个选项一行，默认的那个加了标记；作选项的规定只出现在这个框里。是领域的选项也在框里占一行，它下面的规定仍留在列表里，挂在它的分组行下，比 one-of 所在的领域低一级：one-of 不作分组。筛选把这个框当作一个条目，用 one-of 的状态、领域和默认开关，以及作选项的规定的 `uses`。领域不单占一行：每条规定带着它最近的领域的一条分组行，写着那个领域的编号 (`R13`) 和它所在各层领域组成的路径 (`Documentation › Design`)，在最近的领域与前一条显示的规定不同的地方出现，每页开头也出现一次，所以列表从下级领域回到上级领域时，会再出现一次上级领域的分组行；规定源不止一个时，路径以规定源开头，写它的象限和名字。表头和分组行在窗口滚动时吸在顶上，分组行吸在表头下面，直到下一条分组行把它盖住，只靠样式表。列表上方是图例，每类标记一行 ([前端](frontend.md#components))，列出规定在列表里带的每种标记：各个状态、默认开启和默认关闭、`uses` 的两个值、one-of 的选项，网站上有的话，还有是否启用和象限；最后一行说明标记各个位置的顺序。图例下面是筛选：一个按钮，点开是一个勾选面板 ([前端](frontend.md#components))，每个字段一组：每种状态、默认开启和默认关闭、`uses` 的每个值、每个领域，规定源不止一个时还有每个象限，每组都带「全选」和「不选」。每个字段里都有它的某个值被勾上，规定才显示：它的状态、默认值是否启用它 (答案取决于别的规定源的节点，这个位置空着，算作默认关闭)、它的 `uses` (文件里没写时是 `["instructions"]`)、它最近的领域和它的象限；勾上或取消一个领域时，它下面的领域跟着变。改动立即生效。`parent` 在另一个规定源里的节点，以及带 `overrides` 的规定，在网站上没有领域：它们在树的最顶层，上面没有分组。上级是网站读到的某个规定源里的领域时，筛选按那个领域算；否则只有全部领域都勾上时筛选才显示它们；没有脚本时，它们出现在前面那条分组行下面。本仓目前没有这样的节点；第一个加入这种节点的 pull request 负责修好列表，而第一方规定源不覆盖任何规定。筛选默认勾上 `web/hugo.toml` 里 `params.rulesStatuses` 列出的状态和其余全部的值；已被取代、已废止和草案状态的规定都在列表里，但默认不勾。筛选旁边的下拉框设定每页条数：默认全部 (`params.rulesPerPage`)，也可以选 25 条、50 条或 100 条；先筛选，再分页。筛选后面是一个分段控件，设定每行显示什么 ([前端](frontend.md#components))：默认显示标题和要求，也可以只显示标题，或者只显示要求；样式表按勾上的单选按钮显示各行，所以没有脚本也能切换，而且不论哪一档，每条要求都在页面里。`web/assets/ts/rules-view.ts` 勾上地址里 `?view=title` 或 `?view=statement` 写明的那一档，地址里没有 `view` 就是默认那一档；进入一个不带它的地址时，用读者上次选的那一档 (保存在浏览器的 `localStorage` 里)，并把它写进地址。每次切换都在历史记录里加一条，后退和前进回到各自地址写明的那一档。Hugo 按默认筛选生成页面，默认全部规定都在一页上，`params.rulesPerPage` 是数字时 (测试里这样设) 生成各页；每页都含全部规定，每条规定都带着它的分组行，不显示的隐藏起来。`web/assets/ts/rules-list.ts` 由 Hugo 打包 ([前端](frontend.md#in-the-code))，内联在 `<head>` 里，从地址里读出筛选、每页条数和页码，显示这一页的规定和分组行，重新生成页码链接，每次改动都写回地址。地址里只写勾选与默认不同的字段，每个字段写勾上的值，都是由 `[a-z0-9-]` 组成的键，用逗号隔开：`?status=draft,trial&uses=review&domain=14,15&per=50&page=2`，一个状态都不勾时是 `status=`；`per` 只在每页条数不是默认值时写，所以地址里没有它就显示全部规定，带着它的 (包括 `per=100`) 照旧按它分页。旧格式的地址，即 `filter=1` 加上每个勾上的框一个参数，没有参数的字段就是一个都没勾 (`?filter=1&status=draft&uses=review&default=on&domain=14`)，读成同样的筛选，并改写成新格式。没有脚本时这些控件隐藏，沿用 Hugo 生成的分页。规定列表没有目录，窄屏顶栏上也没有打开目录的按钮 (`BookToC` 关掉)：吸顶的分组行标明眼前的领域。规定的详情页 (`web/layouts/rules/page.html`) 给出编号和标题，标题下面像列表里一样标明默认值是否启用它；规定源不止一个时，标题下面写出它所在规定源的象限和名字 (「全局私有 · team」)，给了 `--enabled` 时还标明是否启用；被取代的规定写明取代它的那些规定；然后是要求、理由和核验方法，它引用的条款 (`authority`)，链接到首页上这些条款的锚点；它的关系 (上级，带 `overrides` 的规定则是「覆盖」和它覆盖的那条规定；依赖和冲突，冲突只写在一边，两条规定上都显示)；以及全部元数据：ID、修订号、类型、状态、slug、默认层级、适用的宪法修订号、检查方式及其命令和工具、`default`、`uses`、原文语言和译文。领域或 one-of 的页面列出它下面的节点：one-of 的页面在其中标出默认选项，它的元数据把这个选项写作 `default`；领域的元数据给出它的 `default`；领域有 applicability 时，它的页面把它放在标题下面，其中的引用像规定正文一样变成链接。页面上提到的节点都显示编号和标题；目录列出页面上的各个标题。正文里的 `{@constitution:...}` 变成指向该条款锚点的链接，链接文字是完整版给它的称呼，用正文的语言；`{@rule:N}` 变成指向那条规定详情页的链接 (「rule N」、「规定 N」)。占位符 `{$language.docs}` 变成参数的默认值，按输出在正文语言里的写法写出 (「English」「英文」)，并标成一个取值：它链接到参数在所属规定源参数页上的条目，参数名作为链接的 title，鼠标悬停时显示；在代码片段里时，整个代码片段改写成包着这个链接的 HTML。标题在列表、one-of 的框和页面上提到的节点里本身就在链接里，列表里的要求也一样 (`statementInLink`，其中的引用只写称呼，不加链接)，所以那里的取值标成一个 span，参数名作为它的 title，做了转义，不加链接；在规定自己的详情页上，像正文一样标记并加链接；在别的地方只写出取值。标题里的代码片段在页面上一律显示成代码：列表和规定自己的详情页上的标题由 Hugo 渲染；首页的 content adapter 渲染不了 Markdown，所以 `site-rules` 给规定数据里提到的每个节点和条款下的每条规定另外提供 HTML 形式的标题 (`titleHtml`：正文只转义一次，每个代码片段变成一个 `<code>`)；条款下规定的链接，名字就是去掉标签的这段 HTML。页面自己的标题，即浏览器标签页上的标题，是去掉反引号的纯文本标题。有参数的规定源各有一个参数页，本仓的是 `rules/params/`，别的规定源是 `rules/<name>-params/` (`web/layouts/_partials/rules/params.html`)，链接放在列表上方：每个参数一个标题，写它的 title，锚点是它的名字，下面列出名字、类型、`choice` 的可选值、范围、默认值，以及正文里用到它的规定。别的规定源的规定里的占位符，指那个规定源的参数，没有时指本仓的参数。节点本来就用页面的语言写成，或者有这种语言的译文时，页面用页面的语言显示它的正文；否则显示原文，上面有一行写明原文的语言 (`这条规定还没有中文译文，下面是原文 (英文)。`)，正文带上相应的 `lang`。`statute export` 遇到依据旧原文翻译的译文会失败，`site-rules` 也随之失败，所以页面拿到的译文都跟随当前原文。首页上被某条列出的规定引用的每个条款下面，首页的 content adapter 加一行：先是直接引用它的每条规定的链接，编号放在一个胶囊里；有规定只引用了它下级的条款时，后面是一个按钮，写着这些规定的条数，前面有直接引用的规定时写「另有 N 条引用下级条款」，没有时写「N 条规定引用下级条款」，按钮前面是一个圆圈里的加号。点一下，或者按 Enter、空格，这些规定的链接就在同一行里显示在按钮前面，圆圈里换成减号；再点一下，或者焦点在这一行里时按 Escape，就收起来，焦点留在按钮上；按钮的 `aria-expanded` 标明当前状态，`aria-controls` 指向这些链接 (`web/layouts/_partials/rules/cites.html`、`web/assets/cites.js`)。这一行放不下时折行。链接的无障碍名称是规定的编号和标题。这一行在条的标题之后，或者在款、项第一行的末尾，由样式表排成单独一行；没有脚本时所有链接都显示，按钮隐藏。长度按不含这些行的正文计算。规定的各页沿用设计的布局和样式 (`<div class="design rules">`)。
- 长度：列表的第二项给出 agent 版的长度，不加说明，因为占用 agent 上下文的就是它：从 `# ` 标题算起的生成文件，两种语言都给字符数，英文还给按空白分隔的词数 (ASCII 空白，文件里只有这一种)，以及 token 数，由 Anthropic 的 count_tokens API (`POST /v1/messages/count_tokens`，只用标准库) 按 `web/hugo.toml` 中 `params.tokenCount.model` 那个模型统计。字符数和词数由 content adapter 统计；token 数由 `count-tokens` 统计，写进 `web/data/lengths.json` (不提交)，同时写入所统计的每段文本的 SHA-256 和运行时所在提交的完整 SHA。只有 SHA-256 与正在构建的文本一致时，网站才显示 token 数和那个提交，所以别的提交留下的文件不会显示过时的数字；没有这个文件时，页面说 token 未统计。长度后面有一个信息按钮，鼠标悬停、点击或轻触都会打开一个弹窗；它是一个展开按钮 (`aria-expanded`)，可以用键盘到达，按 Escape 关闭 (`web/assets/count-info.js`，内联在 `<head>` 里)。弹窗紧贴按钮挂下来，中间没有空隙，在长度下方居中，至少与长度一样宽，这样指针移到弹窗里的链接上时不会离开它；窄屏上它占满整栏。弹窗先说明它所在的那个长度是 agent 版的，再用一张小表给出两个版本的长度 (用带 ARIA 表格角色的 span，读屏软件能读出列名；完整版是从 `# ` 标题算起的生成文件，锚点和链接定义都算在内；没有统计的 token 数显示为一条短横线)，表格与弹窗同宽；表下是一个比表格更淡的项目列表 (用带 ARIA 列表角色的 span)：agent 版略去了什么，哪个 API 为哪个模型统计了 token、或者为什么没有统计 (模型除了 ID，还用 `params.tokenCount.name` 写出它的名称)，以及统计时的修订号和提交，提交缩写为七个字符，链接到源仓库里的那个提交，在新标签页中打开 (没有这段文本的统计，或者不在 git 里时，不显示)；最后单独一行，是 agent 版页面的链接。弹窗文字与标题下星号说明的字号相同，表格里的数字略大一些。每个页面的两个版本分别统计，所以带凭证的一次构建要调用四次 API。
- 凭证：只从环境变量读取，从不来自本仓里的文件，放在两个变量之一中。`CONSTITUTION_TOKEN_COUNT_API_KEY` 存放 API key，以 `x-api-key` 发送。`CONSTITUTION_TOKEN_COUNT_ACCESS_TOKEN` 存放一个短期有效的访问令牌，由工作流通过 Anthropic 的 Workload Identity Federation 取得 (用它的 OIDC 令牌在 `POST /v1/oauth/token` 换取)，以 `Authorization: Bearer` 发送；两个都设置时用令牌，这样遗留的 key 不会盖过 federation。凭证从不出现在输出、日志或页面里；失败时只打印一行，写 HTTP 状态码或异常的类名。没有凭证，或者调用失败，或者连接或读取卡住 10 秒，页面就说 token 未统计，构建继续；带 `count-tokens --require-tokens` 时则统计失败，不写文件。`.github/workflows/pages.yml` 的 job `build` 只在 `main` 上运行 (federation 规则接受本仓任何分支上的运行，不只是 `main`；只发布 `main` 是本仓自己的选择)，而且不在任何 environment 里运行，因为那会改变令牌的 subject：它向 GitHub 要这次运行的 OIDC 令牌 (audience 为 `https://api.anthropic.com`)，用 federation 规则、组织、服务账号和 workspace 的 ID 把它换成访问令牌，这些 ID 存为仓库 secret (`ANTHROPIC_FEDERATION_RULE_ID`、`ANTHROPIC_ORGANIZATION_ID`、`ANTHROPIC_SERVICE_ACCOUNT_ID`、`ANTHROPIC_WORKSPACE_ID`；它们是标识符，不是凭证，但公开仓库的日志谁都能看，而日志会把 secret 遮成 `***`，变量则会原样打印)，用 `--require-tokens` 统计 token，像 CI 一样构建并检查网站，再把两个页面的长度那一行写进 job summary 和日志；与 summary 不同，日志可以通过 API 读取。换取令牌或统计失败，运行就失败，什么都不发布。pull request 上的 CI 拿不到凭证，来自 fork 的 pull request 也拿不到。本地构建想要统计 token，就只为那一条命令设置 key 变量，key 从维护者的密钥管理器里读取。因此，同一个提交的页面在有凭证和没有凭证时会有差别，差别只在那一行和弹窗里。
- 生成器：Hugo，一个单独的可执行文件，在各工作流和 `tools/site/tests/test_site.py` 里固定版本，输出到 `site/` (`publishDir`)；主题是 hugo-book (MIT 许可)，作为 git submodule 放在 `web/themes/hugo-book`，固定在某个提交。主题提供语言切换，浅色、深色和自动三种配色，侧边栏的页面列表，以及右侧的目录。侧边栏列出的是页面而不是条，按 `web/hugo.toml` 的 menus 中命名的组排列：每组是一个顶层条目，组名加粗，前面有它自己的一个 Lucide 图标 (`params.BookIcon`，命名方式见[前端](frontend.md#in-the-code))，组内的页面是它的子条目。共有三组：宪法，即首页，图标是天平 (`scale`)；规定，即它们的列表，图标是清单 (`list-checks`)，下面不列页面，所以在列表页和每条规定的页面上，标为当前页的是这一组本身；设计，即它的 README 页面，图标是一本打开的书 (`book-open`)，组下是 content adapter 列出的各个文件 (见上文「设计」)。设计组可以收起 (组的 menu 参数里的 `collapse`)：除设计自己的页面外，每个页面上它都是收起的；在设计的页面上它展开，并标出当前页。它用的是主题文件树里的 checkbox 和 label，箭头换成 Lucide 的；收起时箭头朝右，展开时朝下，键盘可以切换。宪法组不收起。宪法组下面是它的各版，新的在前：content adapter 把每个页面的条目加进菜单，名称取自 `index.toml`，写作「2026-10 Edition」/「2026-10 版」，`status` 为 `draft` 时后面跟着「(draft)」/「(草案)」，权重是这一版的年月取负。目前只有一版，它的条目链接到首页；这一版的页面不列出。有好几版、旧版只在自己的页面上并在那里被收录的网站还没有实现：网站只读一版 (见上文「输入」)。agent 版不列出，因为它不是给人读的；首页链接到它 (星号说明和长度的弹窗里)，content adapter 用 `bookHidden` 把它从主题自己的列表里隐去，设计的各页面也这样隐去，由菜单列出，规定的各页面同样隐去。目录列出页面的二级标题，即序言和各条 (`web/hugo.toml` 中的 `markup.tableOfContents`)，上面有它自己的标题；窄屏上，主题把它藏在顶栏右侧的一个按钮后面，点开后显示在正文上方，就像左侧的按钮打开侧边栏一样。目录会标出读者当前所在的条 (`aria-current`)，由 `web/assets/toc-current.js` 设置，内联在 `<head>` 里：取位于窗口高度 30% 那条线上方的最后一个标题，或者正文末尾进入视野后取最后一个标题，用 `IntersectionObserver` 监测，当前所有浏览器都支持它；滚动时不读取任何东西。只用 CSS (`scroll-target-group` 和 `:target-current`) 也能做到，但查看时 (2026-10-13) 只有 Chromium 支持。网站覆盖了主题的侧边栏 (`layouts/_partials/docs/menu.html`)，在站名和语言切换之间放一个指向源仓库的链接，带 Octicons 里 GitHub 的标志 (MIT 许可)；并通过主题的 inject partial 加入两样东西：语言切换那一行右端的配色切换按钮，以及字体。配色切换是一个按钮，像 Docusaurus 的那样在跟随系统、浅色和深色之间循环；它用一个 Lucide 图标 (`monitor`、`sun`、`moon`) 显示当前设置，title 和无障碍名称写明当前设置和下一个设置，文字取自 `web/i18n`。选择保存在 `localStorage` 里，并在页面绘制之前于 `<head>` 中设置。用 submodule 可以让主题的文件不出现在本仓的 diff 里；用 Hugo module 的话，每台构建的机器上都需要 Go。
- 原始 HTML：Goldmark 的 `unsafe` 渲染选项是打开的，因为锚点 (`<a id="...">`) 和星号都是原始 HTML。内容只有本仓自己构建出的宪法、设计和规定，从来没有外部输入。
- 锚点：条、款或项的 ID：`#general-provisions`、`#terms`、`#terms.principal`，两种语言相同，Markdown 里也相同。引用是指向它的引用式链接。`:target` 会让锚点所在的元素闪一下。
- 样式：`web/assets/styles/` 里的样式表，页面的每个部分一份，接在主题自己的样式和设计 token 后面 ([前端](frontend.md#in-the-code))。`constitution.css` 只用页面自己的标记和 token，可以原样搬到别的生成器；`site.css` 把 token 映射到 hugo-book 的变量上。条标题居中，款和项的编号加粗 (Markdown 里就是粗体)，英文左对齐、右边不齐，中文两端对齐，打印样式不带链接装饰。正文、标题下和弹窗里的每个链接都像引用一样加下划线：文字用正文颜色，下划线是分隔线颜色的浅线，指针悬停时两者都变成强调色。目录和窄屏的顶栏不加下划线，但在指针悬停或键盘焦点所在时加；侧边栏的链接是一行一行的条目，样子见[前端](frontend.md#components)，当前页面靠底色、颜色和字重标出。目录与正文区分开，颜色较淡，沿一条细线排列；当前的条加粗，用强调色，并在细线上加一道竖条，所以不只靠颜色来区分。正文字号随窗口变化，限定在下限和上限之间 (`clamp()`)，栏宽以 em 为单位，所以窗口够宽时，英文一行约 90 个字符 (36em，按正文的整行测量：EB Garamond 的字母比 `ch` 窄；常用的 75 个字符对这份文本来说太窄)，中文约 40 个字。窗口窄于 70rem (1120 像素) 时，三栏会让英文正文每行少于约 65 个字符，所以这时目录收到主题顶栏的按钮后面，按钮浮在右上角，点开后目录覆盖在正文右侧；侧边栏一直保留到 hugo-book 的断点 (56rem)，小于它时主题也把侧边栏隐藏。正文栏在侧边栏和目录之间居中。字体：EB Garamond 和 Noto Serif SC (SIL Open Font License 1.1)，从 Google Fonts 以可变字体加载，回退到本地的衬线字体。颜色就是[前端](frontend.md#color) 一节的 token，对比度也写在那里。
- 网站本身的少量中文字符串 (`web/i18n/zh.yaml`，存放标签和弹窗文字，以及 `hugo.toml` 里的语言标签和菜单名称) 不在 limae 的检查范围内。
- `site/` 不提交：生成的页面一旦提交、进入审查，每个修正案都会改动它们，而修正案只能改动宪法源文件和它们生成的 Markdown。Hugo 需要下载，所以构建不作为提交钩子；模板的测试 (`test_site.py`，它会构建一部虚构的宪法和一份虚构的设计) 在没有 Hugo 时跳过，CI 除外；CI 在测试之前安装 Hugo。
