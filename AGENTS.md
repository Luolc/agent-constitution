# AGENTS.md

Repo-specific notes for coding agents working on agent-constitution.

This repo holds the constitution for coding agents, the general rule
library and skills, and (later) the toolchain that compiles them, together
with a private overlay, into the one instruction file the agents read. It is
in draft: today it has the constitution and the general rules as TOML
sources, the design and the script that builds the constitution; the rule
compiler is not written yet.

## Language

Everything in this repo is English: code, comments, docs, commit messages,
PR titles and bodies. The one exception is the `zh` text of a bilingual
source: the constitution and rule sources are TOML files whose text tables
have one key per language, `en` and `zh` (format in `docs/design.md`,
Source formats). Write the `zh` text in plain, natural simplified Chinese
that says what the `en` text says, clause by clause, not word by word.
Cite the same provisions and rules as the `en` text; the build checks it.
Punctuation: full-width commas, full stops, enumeration commas, semicolons
and colons; half-width parentheses, with one space outside and none inside,
as in `第二款 (见第三条)`.
Code, paths, commands and IDs stay as they are, with half-width
punctuation.

## Layout and docs

- `constitution/`: the constitution sources, `index.toml` and one
  directory per article, `articles/<NN>-<id>/`, holding `article.toml` and
  one `<NN>-<id>.toml` per section, each with its items inside it; each
  text in both languages. While the constitution is a draft, a new section
  takes the next number and the ones after it are renamed; only after the
  first approved revision does one inserted between two others take a
  suffix, `<NN>a-<id>.toml`. A
  change to their text follows the constitution's amendment procedure;
  what the constitution protects is in `docs/design.md` (File structure).
  Article and section numbers are the name prefixes, written nowhere else;
  while the constitution is a draft they may change and the files are
  renamed with them, and once it is active they never change and a section
  never moves to another article (`docs/design.md`, Numbering).
- `rules/<id>.toml`: one general rule per file, both languages, checked by
  the same build. A rule may be deleted; its ID then goes into
  `rules/retired-ids.txt` and is never used again.
- IDs are dateless words and citations are written `{@...}`: without a
  prefix in the constitution, with `constitution:` or `rule:` in a rule
  (`docs/design.md`, IDs).
- `constitution/constitution.<lang>.md` (the full version) and
  `constitution/constitution.<lang>.agent.md` (the version for agents) are
  generated by `tools/build_constitution.py`, two per language in
  `index.toml`. Never edit them by hand: edit the sources, rebuild, and
  commit the sources and the generated files together.
- `web/`: the Hugo project of the static site (config, layouts, style
  sheet), with the theme hugo-book as a submodule at
  `web/themes/hugo-book`; run `git submodule update --init` once after
  cloning. `tools/build_site.py` builds the two pages into `site/`, which
  is never committed (`docs/design.md`, Static site).
- `docs/design.md`: the one design doc. A PR that changes how the repo
  works (layout, source formats, compilation, checkers, releases) updates
  the section it touches in the same PR. There are no other design or
  decision files.
- The full directory plan, with what belongs to which stage, is in
  `docs/design.md`. Do not create a reserved directory before its stage.
- Never commit a compiled instruction file for a real user. The only
  compiled output here is the golden output of the fictional example
  overlay.

## Content rules

This repo will be made public. Write every file, commit message and PR text
as if it already were:

- No private information: no machine or host names, ports, secret-store
  paths or account names, issue-tracker numbers, chat channels or user IDs,
  people's names or email addresses, names of private repos (call the
  private side "the private overlay"), names of agent instances or
  sessions, and no "who said what, when, relayed by whom". Provenance stays
  on the private side.
- Self-contained: no pointer to rules, files or documents outside this repo
  that a public reader cannot see. A rule that is needed is written here; one
  that is not, is left out.
- One fact in one place; elsewhere, link to it. Do not write values that go
  stale (versions, model names, external tool behavior) unless needed, and
  then with the date they were read.
- Test data and examples use made-up values only: `example.test` domains,
  documentation address ranges (192.0.2.0/24, 198.51.100.0/24,
  203.0.113.0/24, 2001:db8::/32), fictional names.
- Public projects may be named, for example fleet and herdr.

Before a push, search the diff for each class above and check that the
search reads content: run the same search on a file where it must match.

## Checks

- `uvx pre-commit run --all-files`: the commit hooks, which are gitleaks on
  the staged diff, `python3 tools/build_constitution.py --check`,
  `python3 -m unittest discover -s tools`, `tools/lint_zh_sources.py` and
  limae on `constitution/constitution.zh.md` and
  `constitution/constitution.zh.agent.md`. Install the hooks once after
  cloning with `uvx pre-commit install`. The hooks install `limae` for
  themselves; the tests and `tools/lint_zh_sources.py` run by hand need it
  on PATH.
- `python3 tools/build_constitution.py`: rebuilds the generated files
  after a change to the constitution sources. With `--check` it writes
  nothing and fails on an error in the constitution or rule sources or a
  stale generated file; `--check --base <git-ref>` also fails when a
  numbered provision of an active base commit is gone, renumbered or moved,
  or a rule of that base is gone without being retired (a draft base is
  skipped with a note); `--root <dir>` runs it on another
  checkout.
- `python3 tools/check_instruction_changes.py --base origin/main`: fails
  when the branch changes instruction files (the path table at the top of
  the script) together with other files; generated files do not count.
  Run it before a push; CI runs it on every pull request.
- `python3 tools/lint_zh_sources.py`: runs limae on the `zh` text of the
  constitution and rule sources and prints `file:line: field: finding`;
  `--fix` writes limae's fixes back into the sources. A limae finding in
  either built Chinese file is fixed in the sources or the build script,
  never in that file.
- `python3 tools/build_site.py`: builds the static site into `site/`,
  English at `site/index.html` and Chinese at `site/zh/index.html`, then
  runs `tools/check_site_anchors.py` on it (every in-page link has its
  target, no id repeats, no list marker leaked into the text). It calls
  the binary `hugo-0.167.0`, the version CI pins; it is not a commit hook.
  To look at the pages, serve them: `python3 -m http.server -d site`.
- `gitleaks git --redact --no-banner --verbose .`: the full-history scan
  that CI runs. Keep `--redact`; without it a hit prints the secret.

## CI

`.github/workflows/ci.yml` runs on pull requests and on pushes to `main`. Its
one job, `check`, scans the full history with gitleaks (pinned by version and
SHA-256), runs `pre-commit run --all-files` with the gitleaks hook skipped,
so the constitution build check, the tests and both limae checks run there
too, builds the static site with the pinned Hugo and checks its links, and
then runs the build check with `--base` and the instruction-only check,
both against the pull request's base commit, or on a push to `main` against
the commit before the push. `check` is the required status check on
`main`: a merge waits for it to pass. Runners are pinned to
`ubuntu-24.04`, and actions by commit SHA.

## Fleet

For leads and workers that `fleet` starts in this repo.

- Open your own worktree with `fleet worktree agent-constitution --branch
  <type>/<short-desc>`, or work in the one your lead names. A reviewer's
  checkout of a PR head is `fleet worktree agent-constitution --name <name>
  --detach <head-sha>`, never a bare `git worktree add`: fleet removes what
  it recorded at `fleet job end`.
- Instruction files change in a task and a PR of their own
  (`rules/instruction-only-changes.toml`); CI fails a PR that mixes them
  with other files. The constitution sources (`constitution/index.toml`,
  `constitution/articles/`) change in a PR of their own, with no other
  file but the regenerated `constitution/constitution.*.md`.
- Worker report (`fleet done --report-file`): what was done, the PR and its
  merge commit, the checks run and CI's `run_attempt`, why done or
  abandoned, and follow-ups left.
- Done means the PR is merged. Abandoned means you stop without a merge and
  say why. The lead reads the reports and decides what comes next.
- This repo has no natural key for a job. Before starting one, look at
  `fleet job list` and the open issues, and ask in the thread when unsure.
